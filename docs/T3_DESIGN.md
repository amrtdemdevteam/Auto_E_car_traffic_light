# T3 Traffic Controller — Design

**สถานะ:** ออกแบบเสร็จ ยืนยันกติกากับเจ้าของระบบแล้วเมื่อ 28 ก.ย. 2026 · โค้ดยังไม่ผ่านการทดสอบภาคสนาม
**ขอบเขต:** ตัวควบคุมบน Raspberry Pi, เฟิร์มแวร์จอ ESP32-S3 + HUB75 64×32, OTA ผ่าน LAN, หน้าเว็บตั้งค่าและดูสถานะ
**เอกสารประกอบ:** `docs/T3_presentation/T3-logic.pdf` (ภาพประกอบ 13 หัวข้อ) · backup ก่อนเริ่ม: `AutoEcar_git_BK_20260928/` (commit f52cb87)

เอกสารนี้เป็นแหล่งอ้างอิงหลักของ T3 เมื่อมีเอกสารอื่นขัดกัน ให้ยึดเอกสารนี้ ค่าตัวเลขทุกตัวอยู่ใน config แก้ได้จากหน้าเว็บโดยไม่ต้องแก้โค้ด

## 1. หลักการ

1. **เขียวทีละเลน ห้ามเขียวพร้อมกันเด็ดขาด** มีตัวแปร `active_lane` ได้ไม่เกินหนึ่งค่า และเปิดเขียวเลนใหม่ได้เฉพาะหลังผ่าน all-red barrier
2. **ค่าเริ่มต้นคือห้ามผ่าน** ไม่มีรถหรือยังไม่ถึงคิว = X แดง ทุกเฟรมที่ไม่ใช่สีเขียวหมายถึงห้ามผ่าน
3. **ไม่แน่ใจ = ไม่เขียว** เปิดเครื่อง, รีบูต, สายหลุด, คำสั่งหมดอายุ, config ผิด → จอไม่แสดงสีเขียว
4. **กล่อง A เป็นผู้ตัดสินใจเพียงจุดเดียว** จอแค่แสดงผลตามคำสั่ง และตัดสินใจเองได้อย่างเดียวคือเลิกเขียวเมื่อคำสั่งหมดอายุ
5. **โค้ดชุดเดียวทุกแยก (T1–T6)** ต่างกันแค่ config ของแต่ละแยก หนึ่ง Pi ดูแลหนึ่งแยก
6. **V1 (แยกปกติ J1) ยังใช้งานได้เหมือนเดิม** เลือกโหมดด้วย `junction_type` (`normal` = V1, `t3` = คิว T3)

## 3. การกรองสัญญาณเซนเซอร์

### 3.1 เซนเซอร์ตรวจรถ (C1.1, C1.2, C2, C4)

| ชั้น | เงื่อนไข | ค่า |
|---|---|---|
| raw detect | ระยะอยู่ในช่วง และความแรงถึงเกณฑ์ | 30–190 cm · strength ≥ 100 (พื้นวัดได้ 220–241 cm) |
| rising (มีรถ) | raw detect ต่อเนื่องครบ debounce | 0.2 s (ค่าเดียวทุกตัว) |
| filtered clear (รถพ้น) | ไม่มี raw detect ต่อเนื่องครบ gap hold จากเฟรมที่สดและ valid (เลน Auto 1.2 s · เลน Manual ทุกแบบ 0.2 s `manual_gap_hold_s`) | 1.2 / 0.2 s |
| offline (เสีย) | ไม่มี valid frame | 2.0 s |
| online กลับมา | valid frame ต่อเนื่อง | 1.0 s |

- ช่องว่างระหว่างรถกับ dolly ~1 m (0.5 s ที่ 2 m/s และราว 1 s ตอนเพิ่งออกตัว) จึงคง gap hold 1.2 s ไว้ที่เลน Auto ส่วนเลน Manual ใช้ `manual_gap_hold_s` = 0.2 s เพื่อแยกรถที่ขับชิดกัน (ต้องจูนจากสัญญาณจริงรถ + dolly)
- **Auto จ่อตูดแยกคันไม่ได้**: ช่องว่างระหว่างคัน (0.5 m ≈ 0.25 s) สั้นกว่าช่องว่างรถ–dolly ในขบวนเดียวกัน จึงนับเป็นขบวนยาวขบวนเดียว ไฟเขียวยังต่อเนื่องถูกต้อง
- **เซนเซอร์ offline หรือข้อมูลค้างไม่นับเป็น clear เด็ดขาด** filtered clear เกิดได้จากเฟรม valid ที่สดเท่านั้น ถ้าเซนเซอร์หายไประหว่าง occupied สถานะเป็น "ไม่ทราบ" และเข้ากติกาเซนเซอร์เสีย (หัวข้อ 7)
- ช่วงที่ข้อมูลขาดนานกว่า `fresh_timeout_s` ไม่นับรวมใน debounce และ gap hold: นับใหม่จากข้อมูลที่กลับมา · ตรวจมือก็นับเฉพาะเฟรมที่สด
- ทุกค่าตั้งแยกรายเซนเซอร์ได้ (`sensors.<id>.*`) ถ้าไม่ตั้งใช้ `sensor_defaults`
- rising edge แต่ละครั้งมีหมายเลข (`edge_id`) ใช้ป้องกันการสร้างตั๋วซ้ำจาก edge เดิม

### 3.2 เซนเซอร์ตรวจมือ (C3, C5)

| ค่า | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| ระยะ | นับเป็นมือถ้าอยู่ในช่วงนี้ (พื้นต้องไกลกว่าค่าสูงสุด) | 30–190 cm · strength ≥ 100 (พื้น C3 234, C5 220 cm) |
| `hand.hold_s` | ค้างมือต่อเนื่องครบแล้วได้ตั๋ว | 3.0 s |
| `hand.grace_ms` | มือหลุดสั้นกว่านี้นับต่อ นานกว่านี้เริ่มนับใหม่ | 300 ms |
| `hand.confirm_show_s` | แสดงภาพยืนยันหลังได้ตั๋ว | 1.0 s |
| `hand.rearm_clear_s` | ต้องไม่เห็นมือต่อเนื่องเท่านี้ก่อนขอตั๋วใหม่ได้ | 0.5 s |
| `hand.max_pending_per_lane` | ตั๋วรอได้ต่อเลน | 1 |

ลำดับสถานะ: `IDLE → SEEN (0–1 s) → PROGRESS_1 (1 s) → PROGRESS_2 (2 s) → CONFIRMED (3 s = ได้ตั๋ว) → WAIT_REARM → IDLE`

- จอแสดง "เห็นมือ" ทันทีที่เห็น ไม่มี debounce เพื่อให้คนที่แกว่งแขนหาจุดรู้ว่าเซนเซอร์เห็นแล้ว
- การแกว่งแขน: แขนผ่านลำแสงแล้วหลุดเกิน 0.3 s ทุกครั้ง การนับจึงเริ่มใหม่ ไม่เกิดตั๋ว
- ยื่นมือซ้ำระหว่างที่เลนมีตั๋วรออยู่แล้ว ไม่เพิ่มตั๋ว จอกลับเป็น X ปกติ
- ตั๋วที่ได้แล้วค้างในคิวแม้เอามือออก

## 4. คิว

### 4.1 ตั๋ว (Ticket)

| ฟิลด์ | ความหมาย |
|---|---|
| `id` | เลขตั๋วเพิ่มขึ้นเรื่อย ๆ |
| `lane` | เลขเลน |
| `kind` | `auto` / `manual` / `special` |
| `created_at` | เวลา monotonic ตอนสร้าง |
| `source` | เซนเซอร์ที่สร้าง เช่น `C1.2`, `C1.1`, `C2`, `C3` |
| `matched` | (Auto) C1.1 เห็นรถของตั๋วนี้แล้ว |
| `expires_at` | (Auto จาก C1.2) หมดอายุถ้ายังไม่ matched |

### 4.2 ลำดับการเลือก

1. ตั๋ว Auto ก่อนเสมอ (`priority.auto_first = true`)
2. Manual เรียงตาม `lanes[].priority` (มากกว่า = ก่อน · T3 ตั้งเท่ากันหมด = 0)
3. ความสำคัญเท่ากัน → มาก่อนได้ก่อน (`created_at`)
4. เวลาเท่ากันเป๊ะ → round-robin เริ่มจากเลนถัดจากเลนที่ได้เขียวล่าสุด
5. **คำขอใหม่ไม่ตัดไฟเลนที่กำลังเขียว** เลือกตั๋วถัดไปเมื่อเลนปัจจุบันจบรอบแล้วเท่านั้น
6. Auto มาต่อเนื่อง Manual ต้องรอจน Auto หมด (ยอมรับแล้ว)
7. ตั๋ว Manual ไม่หายเองแม้รถถอยออก ผู้ดูแลเคลียร์ได้จากหน้าเว็บ

### 4.3 ตั๋ว Auto: C1.2 จับคู่กับ C1.1

- C1.2 rising → สร้างตั๋ว Auto (`matched=false`, หมดอายุใน `auto_ticket_expiry_s` = 7.0 s)
- C1.1 rising → จับคู่กับตั๋ว Auto เก่าสุดที่ยังไม่ matched ถ้าไม่มีตั๋วให้จับคู่ C1.1 สร้างตั๋วใหม่ที่ matched แล้ว (ใช้กรณี C1.2 เสีย หรือตั๋วหมดอายุไปก่อน)
- ตั๋วไม่ matched ภายใน 7 s → ทิ้งเฉพาะตั๋วนั้น (log `ticket_expired`)
- เวลาจริง: C1.2 → C1.1 ประมาณ 5 s, รถจอดเช็ค lidar ~2 s แล้วออกตัว

## 5. การให้เขียวแต่ละประเภทเลน

### 5.1 Auto (เลน 1)
1. ตั๋ว Auto อยู่หัวคิวแต่ยังไม่ matched → **แยกรอ ทุกจอ X ไม่ให้ Manual ไปก่อน** (รอได้ไม่เกินอายุตั๋ว)
2. ตั๋ว matched และผ่าน barrier → B1 เขียว
3. ระหว่างเขียว C1.1 rising → ตั๋ว Auto ที่ matched ถูกรวมเข้ารอบนี้
4. C1.1 filtered clear → นับ `auto_clear_s` = 4.0 s (จอยังเขียว ไม่เปลี่ยนภาพ)
5. ครบ 4 s แล้วถ้าหัวคิวยังเป็นตั๋ว Auto → เขียวต่อ ไม่คั่น X (ถ้ายังไม่ matched ให้เขียวรอจน matched หรือหมดอายุ) ถ้าไม่มี → จบรอบ

### 5.2 Manual ปกติ (เลน 2, 4)
1. เซนเซอร์ rising → ตั๋ว Manual
2. ถึงคิวและผ่าน barrier → เขียว
3. เซนเซอร์ filtered clear (หรือว่างอยู่แล้วตอนเริ่มเขียว นับจากตอนเริ่มเขียว) → นับ `manual_clear_s` = 3.0 s
4. ครบแล้วจบรอบเสมอ **ไปทีละคัน ไม่ไหลต่อตูดกัน** รถคันถัดไปที่มาบังเซนเซอร์ระหว่างนับ 3 s ไม่ต่อเขียว ได้ตั๋วใหม่ รอคิวและผ่าน barrier ใหม่ (ถ้าเป็นหัวคิวก็ได้เขียวอีกครั้งหลัง X)
5. ท้ายรถพ้นจริง → X = 0.2 + 3.0 = 3.2 s (ที่ ~7 m/s ≈ 22 m)

### 5.3 Manual พิเศษ (เลน 3, 5)
- ถึงคิวและผ่าน barrier → เขียวคงที่ `special_green_s` = 3.0 s (เท่าเลน Manual · ไม่มีตัวเลขนับถอยหลัง) → จบรอบ
- ไม่ใช้เซนเซอร์นับรถพ้น เริ่มที่ 3 s เท่า `manual_clear_s` ถ้าไม่พอปรับเพิ่มใน config (รายเลนก็ได้)

## 6. ตัวควบคุม (Controller) และ all-red barrier

### 6.1 สถานะหลัก

| สถานะ | ความหมาย | จอ |
|---|---|---|
| `STARTING` | เพิ่งเริ่ม รอจอออนไลน์และเซนเซอร์มีข้อมูล (อย่างน้อย `startup_min_s` = 3 s) | F01 ทุกจอ |
| `IDLE` | ไม่มีเลนเขียว | X / ภาพตรวจมือ / ภาพสถานะเลน |
| `SWITCHING` | all-red barrier ก่อนเปิดเลนใหม่ | X ทุกจอ |
| `GREEN` | มีเลนเขียว 1 เลน (`active_lane`) | ลูกศรเขียวเฉพาะจอเลนนั้น |

### 6.2 Break-before-make (all-red barrier)

ก่อนเปิดเขียวเลนใหม่ทุกครั้ง:
1. สั่งทุกจอเป็นเฟรมที่ไม่ใช่เขียว (seq ใหม่)
2. รออย่างน้อย `switch_all_red_s` = 1.0 s
3. จอที่เคยได้คำสั่งเขียวใน epoch นี้ต้องตอบ ACK ว่าแสดงเฟรมไม่เขียวแล้ว ที่ seq ≥ seq ของ barrier
4. จอเป้าหมายต้องออนไลน์ (ACK ล่าสุดไม่เกิน `display_ack_timeout_s` = 2.0 s)
5. ถ้าจอไหนไม่ตอบภายใน `display_ack_timeout_s` (2.0 s) → ถือว่าจอนั้นเสีย **ปิดเฉพาะเลนของจอนั้น** (ไม่แยกว่าจอเพิ่งเขียวมาหรือไม่) และยังไม่เปิดเลนใหม่จนครบ `display_fault_timeout_s` (6.0 s) นับจากคำสั่ง X ครั้งล่าสุด ซึ่งยาวกว่าอายุคำสั่งของจอ (5 s) จึงแน่ใจว่าจอเลิกเขียวเองแล้ว · ครบแล้วปล่อยผ่าน เลนอื่นทำงานต่อได้เอง ไม่ต้องมีคนรีเซ็ต
6. จอของเลนที่กำลังเขียวหยุดตอบ (ACK เก่ากว่า 2.0 s) → จบไฟเขียวเลนนั้นทันที (`green_ended reason=display_lost`) แล้วเข้าข้อ 5

ระหว่าง barrier จอแสดง X ปกติ ไม่มีภาพพิเศษ

### 6.3 ความปลอดภัยที่รับประกัน (safety invariants · มี unit test)
- `active_lane` มีได้ไม่เกินหนึ่งค่า และคำสั่งเขียวไปได้เฉพาะจอของ `active_lane`
- ทุกการเปิดเขียวผ่าน barrier ข้อ 6.2 ครบ
- `STARTING` และหลังรีสตาร์ตไม่มีคำสั่งเขียว
- เซนเซอร์ของเลนที่เขียวอยู่เสีย → เลิกเขียวทันที (ผ่าน all-red barrier + จอ ACK ตามปกติ) ปิดเฉพาะเลนนั้น เลนอื่นทำงานต่อ
- จอไม่ยืนยันเฟรมไม่เขียว → ไม่เปิดเลนใหม่จนครบ `display_fault_timeout_s`
- เลนที่ปิดใช้ (ปิดซ่อม, เซนเซอร์เสีย, จอเสีย, config ผิด) ไม่ได้เขียว

### 8.1 ค่ารวม (global) กับค่ารายเลน (local)

- **ค่ารวมของแยก** ใช้ร่วมทุกเลน: `timing.switch_all_red_s`, `display_ack_timeout_s`, `display_link_timeout_s`, `display_fault_timeout_s`, `command_refresh_s`, `startup_min_s`, `priority.auto_first`, `sensor_defaults.offline_timeout_s` / `recover_stable_s`, OTA, MQTT

- **ค่ารายเลน** `lanes[].params` ทับค่าเริ่มต้นของประเภทได้เฉพาะ key ของประเภทนั้น (เว้นว่าง = ใช้ค่าเริ่มต้น) เช่น `{"special_green_s": 6.0}`
- **ค่ารายเซนเซอร์** `sensors.<id>` ทับ `sensor_defaults` ได้: `min_detect_cm`, `max_detect_cm`, `min_strength`, `debounce_ms`, `gap_hold_s`

ประเภทเลนมี 2 แบบ: `"type": "auto"` หรือ `"type": "manual"` + `"mode": "vehicle"` (ตรวจรถ) / `"hand"` (ยื่นมือ) · ค่าเก่า `"type": "special"` ยังใช้ได้ (= manual + hand) · ชื่อเซนเซอร์ตั้งจากเลขเลนอัตโนมัติ: Auto `C<n>.1` ใกล้/ยืนยัน, `C<n>.2` ไกล/แทรกคิว · Manual `C<n>`

ขอบเขตที่หน้าเว็บยอมให้บันทึก: เวลาทุกค่า > 0, `grace_ms` 100–1000, `switch_all_red_s` ≥ 0.5, `display_fault_timeout_s` ≥ `display_link_timeout_s` + 1, ระยะ min < max

## 10. โปรโตคอล MQTT (Pi ↔ จอ)

broker: Mosquitto บน Pi `10.77.0.1:1883` (LAN จอแยกจาก Wi-Fi) · base = `factory/trafficlight/<junction_id>`

| topic | ทิศ | retain | payload |
|---|---|---|---|
| `<base>/display/<n>/cmd` | Pi → จอ | **ไม่ retain** | `{"epoch":"a1b2c3d4","seq":1287,"frame":"GO","arg":"","ttl_ms":5000}` |
| `<base>/display/<n>/ack` | จอ → Pi | ไม่ | `{"epoch":"a1b2c3d4","seq":1287,"frame":"GO","green":true,"fw":"t3-1.0.0","up_s":3600}` |
| `<base>/display/<n>/status` | จอ → Pi | retain · last will `offline` | `online` / `offline` |
| `<base>/controller/status` | Pi → จอ | retain · last will `offline` | `online` / `offline` |
| `<base>/control` | หน้าเว็บ → Pi | ไม่ | `{"cmd":"maintenance","lane":3,"on":true,"user":"engineer01"}` |
| `<base>/state` | Pi → หน้าเว็บ | ไม่ (ทุก 0.5 s) | สถานะเต็ม (เลน คิว เซนเซอร์ จอ log) |

กติกาฝั่งจอ:
- บูตแล้วแสดง F01 จนได้คำสั่งแรกที่ถูกต้อง ไม่มีคำสั่ง retain ให้รับ จึงไม่มีทางได้คำสั่งเขียวเก่า
- `epoch` คือรหัสสุ่มของรอบการทำงานของ controller เปลี่ยนทุกครั้งที่ controller เริ่มใหม่ จอรับ epoch ใหม่เสมอ และทิ้งคำสั่งที่ `seq` ไม่มากกว่าตัวล่าสุดใน epoch เดียวกัน
- คำสั่งมีอายุ `ttl_ms` (5000) Pi ส่งซ้ำทุก `command_refresh_s` (1 s) ถ้าหมดอายุ → F11
- ได้ `controller/status = offline` → F11 ทันที
- วาดเสร็จแล้วส่ง ACK ทุกคำสั่ง
- Pi ส่งคำสั่งทุกจอเมื่อมีการเปลี่ยนและทุก 1 s เป็น heartbeat

## 11. OTA (อัปเดตเฟิร์มแวร์ผ่าน LAN)

- ใช้ไลบรารี `jandrassy/ArduinoOTA` ที่รองรับ W5500 (Ethernet) + ESP32 (`InternalStorageESP` เขียนลงช่อง OTA ที่ว่าง)
- partition `default.csv` บน flash 4 MB มีช่องแอป 2 ช่อง (~1.25 MB ต่อช่อง) เฟิร์มแวร์ปัจจุบัน ~320 KB
- **ต้องแฟลชผ่านสาย USB ครั้งแรกหนึ่งครั้งต่อจอ** หลังจากนั้นอัปเดตทาง LAN ได้
- ขั้นตอน: หน้าเว็บ → เลือกจอ + ไฟล์ `.bin` → Pi สั่งปิดเลนของจอนั้น (MAINT · ปิดหลังจบเขียวรอบนั้น) → ส่งไฟล์ทันที ไม่รอเลนจบเขียว (จอที่กำลังอัปเดตเลิกเขียวเอง → Pi เห็น ACK หาย → จบเขียว + barrier)  HTTP POST ไปที่จอ (พอร์ต 65280, รหัสผ่าน OTA จาก config) → จอแสดง F14 ระหว่างรับ → รีบูต
- **กันเลือกไฟล์ผิดจอ:** เฟิร์มแวร์มีป้าย `T3-DISPLAY-ID:<n>;` ฝังในไฟล์ ตัว Pi อ่านป้ายก่อนส่ง ถ้าเลขไม่ตรงกับจอที่เลือก (หรือไม่มีป้าย) จะปฏิเสธ ไม่ส่ง
- **Watchdog จอ:** เฟิร์มแวร์ตั้ง hardware watchdog `WDT_TIMEOUT_MS` = 8 s ถ้า loop ค้าง จอรีสตาร์ตเอง (ไม่ค้างเขียว) ปิดชั่วคราวระหว่างรับไฟล์ OTA
- **ย้อนกลับอัตโนมัติ:** ก่อนรีบูตจอบันทึก `ota_pending=1` ลง NVS เฟิร์มแวร์ใหม่ต้องได้คำสั่งที่ถูกต้องจาก controller ภายใน 120 s ถึงจะยืนยันว่าใช้ได้ ถ้าไม่ได้ จะสลับกลับไปช่องเฟิร์มแวร์เดิมแล้วรีบูตเอง
- อัปเดตได้ทีละจอ เลนของจอนั้นปิดระหว่างอัปเดต และเปิดกลับเมื่อจอ ACK ปกติ

## 12. หน้าเว็บ

- ทำงานบน Pi ของแต่ละแยก `http://<IP Pi บน Wi-Fi>:8080` หนึ่ง IP ดูแลหนึ่งแยก ไม่ต้องใช้อินเทอร์เน็ต
- เป็น service แยก (`trafficlight-web`) จากตัวควบคุม หน้าเว็บค้างหรือล่ม ไม่กระทบไฟจราจร
- ไม่มี dependency เพิ่ม (Python standard library `http.server`)
- มี 2 หน้าหลัก + หน้าตั้งค่าครั้งแรก

### 12.1 ตั้งค่าครั้งแรก (แสดงเมื่อ config ยังไม่มีเลน · ผู้ที่แก้ไขได้เท่านั้น)

1. หน้าเปล่า กด **+** เพิ่มเลนทีละเลข (เลน 1, 2, 3 …) หรือกด “เริ่มจากผัง T3 ตามแบบ” เพื่อใส่ 5 เลนตามหัวข้อ 2 (พอร์ตว่าง)
2. แต่ละเลนเป็นแถว: `เลข | ประเภท | ภาพจอ | วงกลมสถานะเซนเซอร์ | สรุป | ตั้งค่า +`
3. กดตั้งค่า แผงเลื่อนลงมา:
   - ประเภทเลน: **Auto** หรือ **Manual** · ถ้า Manual เลือก “วิธีขอทาง” ต่อ: **เซนเซอร์จับรถ** หรือ **ยื่นมือ** · ค่าเริ่มต้นของเวลามาตามประเภท
   - จอ: dropdown B1–B7 (IP + ออนไลน์/ไม่พบ · จอที่เลนอื่นใช้แล้วเลือกไม่ได้) · ปุ่ม **ทดสอบ** → จอนั้นขึ้น F27 `TEST B<n>` 5 วินาที เพื่อรู้ว่าจอไหนคือจอไหน
   - เซนเซอร์: Auto 2 ช่อง (ไกล · แทรกคิว / ใกล้ · ยืนยัน) · Manual 1 ช่อง · dropdown พอร์ตแสดงระยะสดของทุกพอร์ต · พอร์ตที่เซนเซอร์อื่นใช้อยู่ (เลนอื่น หรือตัวอื่นของเลนเดียวกัน) เลือกซ้ำไม่ได้ (server ปฏิเสธพอร์ตซ้ำอยู่แล้ว) · ปุ่ม **หาด้วยมือ** → เอามือบังเซนเซอร์ ~2 วินาที พอร์ตที่ระยะเปลี่ยน (≥ 40 cm และ ≥ 30 % ของค่าตั้งต้น ติดกัน 2 รอบ) ถูกเลือกให้เอง · ค่าตรวจจับรายเซนเซอร์อยู่ใน “ค่าตรวจจับของ Cx”
   - เวลาของเลนนี้: ช่องตัวเลข เว้นว่าง = ใช้ค่าเริ่มต้นของประเภท (แสดงเป็นตัวเลขจาง)
   - ขั้นสูง: ชื่อเลน, priority, เปิดใช้
   - **บันทึกเลนนี้** → แผงปิด แถวแสดง ✓ ครบ หรือสิ่งที่ยังขาด
4. เลนครบทุกเลน → **ถัดไป** บันทึกเป็น config เวอร์ชันแรก แล้วไปหน้าแผนที่ (ถ้าเริ่มจากผัง T3 ตามแบบ จะวาดแผนที่ตามแบบให้ด้วย)
5. ระหว่างตั้งค่า ระบบควบคุมทำงานในโหมด CONFIG: ทุกจอแสดง F12 ไม่มีเลนไหนเขียว แต่ยังอ่านทุกพอร์ต (port probe) และรับคำสั่งทดสอบจอได้ · ร่างที่ยังไม่กดถัดไปเก็บไว้ในเบราว์เซอร์ (ปิดหน้าแล้วกลับมาทำต่อได้)

### 12.2 หน้าแผนที่ (หน้าหลัก)

- ซ้าย: แผนที่แยก **ไม่มีแผนที่เริ่มต้น** — ผู้ที่แก้ไขได้กด **✎ วาดแผนที่** แล้ววาดเองในเบราว์เซอร์ (`static/draw.js`): สี่เหลี่ยม วงกลม เส้นตรง ลูกศร ข้อความ + ชิ้นสำเร็จรูป (ถนนตั้ง/นอน ลูกศร พื้นที่แยก pillar กล่อง A เซนเซอร์ ToF ป้ายเลน ทางออก) หรือกด “ผังถนนตามแบบ T3” · เลือก/ย้าย/ปรับขนาด/หมุน/ทำซ้ำ/ย้อน (Ctrl+Z) · ลำดับชั้น: ↑ ขึ้นหน้า / ↓ ถอยหลัง ทีละชั้น (`]` `[`) และ ขึ้นหน้าสุด / ไปหลังสุด · สี่เหลี่ยมและวงกลมใส่ “สูง 3D” และ “ยก” ได้เพื่อใช้ในมุมมอง 3D · สีใช้ token ของธีม จึงเปลี่ยนตามโหมดสว่าง/มืด · เก็บที่ `/etc/trafficlight/drawing.json` (พื้นที่ 1000×700, ≤ 400 ชิ้น) ไม่ใช่ config · ยังอัปโหลดรูป PNG/JPG/SVG เป็นพื้นหลังใต้ภาพวาดได้ · เลนที่วางแล้วแสดงเป็นกล่อง `[เลข | ภาพจอสด | วงกลมเซนเซอร์]` (Auto มี 2 วง: บน = ไกล, ล่าง = ใกล้)
- สีวงกลม: ขาว = ว่าง · ขอบฟ้า = เห็นวัตถุ (ยังไม่ผ่าน debounce) · ฟ้าทึบ = เจอรถ/มือ · แดง = เสีย/ไม่มีข้อมูล · เส้นประ = ยังไม่เลือกพอร์ต
- ขวา: รายการเลน: เลขเลน + ภาพจอ + ป้าย **Auto** / **Manual · จับรถ** / **Manual · ยื่นมือ** + รหัสแจ้งเตือนของเลน (ถ้ามี) + ปุ่ม **+** · เหนือรายการมีการ์ด “การแจ้งเตือน” เมื่อมีเหตุ (หัวข้อ 12.5)
- ปุ่ม **3D / 2D** ที่มุมแผนที่: มุมมอง 3D สร้างจากภาพวาด 2D เอง (พื้นแบนเอียงด้วย CSS 3D · ชิ้นที่ตั้ง “สูง 3D” เป็นกล่อง/ทรงกระบอก · กล่องเลนตั้งตรงหันเข้าหากล้อง) ลากเพื่อหมุนมุมมอง ล้อเมาส์ซูม ปุ่ม ⟲ ⟳ ▲ ▼ ＋ − · 3D ใช้ดูอย่างเดียว ลากวางเลนในโหมด 2D · จำมุมกล้องในเบราว์เซอร์
- มุมบนขวา: สวิตช์ ☀/☾ สลับโหมดสว่าง/มืด (จำในเบราว์เซอร์ ค่าเริ่มต้นตามระบบ) · ปุ่มเต็มจอ (Esc ออก) แสดงแผนที่ + เลนเท่านั้น
- ผู้ที่แก้ไขได้: ลากเลนจากรายการขวาไปวางบนแผนที่ตรงไหนก็ได้ · ลากกล่องบนแผนที่เพื่อย้าย · ปุ่ม ⟳ หมุน 90° · − / ＋ หรือลากจุดมุมขวาล่าง (คีย์บอร์ด `-` `+`) ย่อขยายกล่องเลน 0.5–3 เท่า (เก็บเป็น `scale` ใน layout, เว้นไว้ = 1) · × เอาออกจากแผนที่ · ใช้คีย์บอร์ดได้ (ลูกศรเลื่อน, R หมุน, Enter เปิดแผง) · ตำแหน่งเก็บที่ `/etc/trafficlight/layout.json` (เป็นสัดส่วน 0–1 ของแผนที่) ไม่ใช่ config และไม่ทำให้ระบบควบคุมรีสตาร์ต
- **ดับเบิลคลิก** กล่องบนแผนที่ หรือกด **+** ในรายการ → แผงตั้งค่าของเลนนั้น (จอ + เซนเซอร์ + เวลา) เลื่อนลงมาในรายการขวา ดันเลนอื่นลง · ดับเบิลคลิกอีกครั้ง/กด − ปิด · เปิดได้ทีละเลน
- ในแผงมีปุ่มงานประจำ: ปิดเลน (ซ่อม)/เปิดเลน, ล้างคิว, อัปเดตเฟิร์มแวร์จอ (OTA)
- ผู้ดูอย่างเดียว: เปิดแผงดูค่าสดได้ แต่แก้/ลากไม่ได้
- ปุ่ม **⟲ หมุนจอ** (หัวเว็บ และหน้าเข้าสู่ระบบ): หมุนทั้งหน้าเว็บ 180° สำหรับจอทัชของ Pi ที่ติดกลับหัว (เมนูของจอหมุนเองไม่ได้) · จำเฉพาะเบราว์เซอร์เครื่องนั้น (`localStorage` `tl_rot`) · `?rot=180` เปิด, `?rot=0` ปิด · ทัชยังกดตรงปุ่ม · `static/rotate.js` แปลงพิกัดนิ้ว/เมาส์และกรอบของ element ให้โค้ดลากบนแผนที่ วาดแผนที่ และหมุน 3D ทำงานตามภาพที่เห็น · ไม่เกี่ยวกับจอ LED ของเลน
- ด้านบน: สถานะแยก + คิวย่อ · ใต้แผนที่: คิวเต็ม + เหตุการณ์ล่าสุด

### 12.3 หน้าระบบ

รูปแบบหน้า: แท็บ ค่ารวม / ประวัติ / ผู้ใช้ · แท็บค่ารวมมีเมนูหมวดด้านซ้าย (เลน Auto, เลน Manual, เซนเซอร์, ความปลอดภัย, จอ, ดูแลระบบ) ด้านขวาแสดงค่าเป็นแถว: ชื่อ ⓘ | ค่าเริ่มต้น (แสดงเมื่อค่าไม่ตรง) | ช่องกรอก | หน่วย | ↺ คืนค่าเริ่มต้น · มีปุ่ม “คืนค่าเริ่มต้นทั้งหมวด” · ค่าเริ่มต้นคือค่าในโค้ด (`t3/config.py DEFAULTS`)

ทุกช่องในเว็บมีปุ่ม ⓘ กดแล้วแสดงความหมายของค่านั้น (แทนคำบรรยายยาวใต้ช่อง) · แผงเลนซ่อนค่าละเอียดไว้ใน “ตั้งค่าเพิ่มเติม” (เวลาของเลน, ค่าตรวจจับรายเซนเซอร์, ภาพไฟเขียว, ชื่อ, ลำดับความสำคัญ, เปิดใช้) · ในแผงเลน ↺ = ล้างค่าเฉพาะเลน กลับไปใช้ค่าเริ่มต้นของประเภท

ปุ่ม “ถัดไป” ในหน้าตั้งค่าครั้งแรกกดได้เมื่อ: มีอย่างน้อย 1 เลน · ทุกเลนเลือกประเภท จอ และพอร์ตครบ · ไม่มีแผงเลนค้างเปิด (แสดงเป็นรายการ ✓ ที่แถบล่าง)

บนแผนที่: คลิกกล่องเลน = เลือก → แถบเครื่องมือ (หมุน 90°, ตั้งค่า, เอาออก) ค้างอยู่จนคลิกที่อื่น

| แท็บ | ทำอะไร | สิทธิ์ |
|---|---|---|
| ค่ารวมของแยก | ค่าเริ่มต้นตามประเภทเลน · ค่ากลางเซนเซอร์ · ความปลอดภัยของแยก · เฟรมสำรอง · รหัส OTA · รีสตาร์ตระบบควบคุม / รีบูต Pi | ดู: ทุกคน · แก้: แก้ไขได้ |
| ประวัติ config | ทุกเวอร์ชัน ใคร เมื่อไหร่ เปลี่ยนอะไร · ย้อนกลับ | ดู: ทุกคน · ย้อนกลับ: แก้ไขได้ |
| ผู้ใช้ | บัญชีรายคน 2 สิทธิ์ (แก้ไขได้ / ดูอย่างเดียว) · บันทึกการใช้งาน | แก้ไขได้ |

การบันทึก (แผงเลนและค่ารวม):
1. ตรวจค่า (หัวข้อ 8) ผิดตรงไหนแจ้งภาษาไทย
2. หน้าต่างยืนยันแสดงค่าที่เปลี่ยน + ช่องบันทึกเหตุผล
3. บันทึกเป็นเวอร์ชันใหม่ `/etc/trafficlight/versions/vNNNN.json` แล้วเขียน `/etc/trafficlight/settings.json`
4. ส่งคำสั่ง `apply` → controller รอจนไม่มีเลนเขียว แล้วปิดตัว systemd เปิดใหม่ทันที (~5 s ทุกจอ X) ใช้ค่าใหม่ · ระหว่างรอหน้าเว็บแสดง “บันทึก vN แล้ว ระบบจะใช้เมื่อแยกว่าง”
5. ย้อนกลับเวอร์ชันเก่าได้จากแท็บประวัติ

### 12.4 API ที่เพิ่ม

| API | ทำอะไร |
|---|---|
| `GET/POST /api/layout` | ตำแหน่ง หมุน ขนาด (`scale` 0.4–4 ไม่ใส่ = 1) ทิศรถ (`dir` 0/90/180/270 ไม่ใส่ = ตาม `approach`) ของกล่องเลนบนแผนที่ (POST: แก้ไขได้) |
| `GET/POST /api/drawing` | แผนที่ที่วาดเอง `{items:[...]}` ชนิด rect/ellipse/line/text/road/hatch สีเป็นชื่อ token เท่านั้น (POST: แก้ไขได้ · server ตรวจทุกช่อง) |
| `GET /api/map` · `POST /api/map` · `POST /api/map/reset` | รูปแผนที่ที่อัปโหลด (PNG/JPG/SVG ≤ 4 MB ส่งกลับพร้อม CSP ห้ามสคริปต์) |
| `GET /api/template` | ผัง T3 ตามแบบ (5 เลน พอร์ตว่าง) |
| `POST /api/control {"cmd":"identify","display":n}` | จอ n แสดง F27 TEST 5 s · ปฏิเสธถ้าจอนั้นเป็นของเลนที่กำลังเขียว |
| `GET /api/state` → `ports[]` | ทุกพอร์ต: label, เซนเซอร์ที่ใช้อยู่, ระยะ, ความแรง, อายุข้อมูล · `displays{}` สถานะ online ของจอ (retained LWT) |

### 12.6 เวลาเขียวและเวลารอ (timeline)

หน้าเว็บ (`static/timing.js`) ดูสถานะที่ poll อยู่แล้ว จำว่าแต่ละเลนเขียวจริงกี่วินาที และรอคิวจริงกี่วินาที (เก็บ 8 ครั้งล่าสุดต่อเลน ในเบราว์เซอร์ `t3stats` · รอบเขียวที่เห็นไม่ครบตั้งแต่เริ่มไม่นับ) แล้วใช้ค่าเฉลี่ยนั้นประมาณเวลารอของเลนที่อยู่ในคิว ไม่แตะตัวควบคุม

- แถวเลนด้านขวา: `คิว n` · รอมาแล้ว · **≈อีก x s** (รวม all-red ระหว่างเลน + เวลาเขียวที่คาดของเลนที่อยู่ก่อนหน้า) · Auto ที่รถยังไม่ถึงมี “หมดอายุ” นับถอยหลังจาก `auto_ticket_expiry_s` · เลนที่กำลังเขียว: เลนยื่นมือ “เหลือ” นับถอยหลังจาก `special_green_s` (แม่น) ส่วน Auto/Manual จับรถแสดงเวลาที่เขียวมาแล้ว เทียบค่าเฉลี่ย (จบเมื่อเซนเซอร์เคลียร์ จึงไม่มีเวลาตายตัว) · แถบใต้ตัวเลข: เขียว = ส่วนที่เหลือ/ที่ผ่านไป, ส้ม = เวลารอเทียบกับที่คาด
- การ์ด “ไทม์ไลน์” ใต้แผนที่: แถวละเลน ย้อนหลัง 60 s ถึงข้างหน้า 30 s · บล็อกเขียว = เขียวจริง · ส้ม = รอคิวจริง · กรอบประเขียวอ่อน = **≈ คาดการณ์** · แถบแดงจาง = ทุกจอ X · ป้ายหน้าเลนแสดงเวลาเขียว/รอเฉลี่ย · ยังไม่มีสถิติของเลนไหน ใช้ค่าเดา (`*_clear_s` + 2 s) และติดป้าย ≈
- ใช้ปรับค่า config ให้ตรงหน้างาน: ถ้าเวลารอเฉลี่ยของเลนไหนสูงผิดปกติ ให้ดูว่า `*_clear_s` ของเลนที่เขียวก่อนหน้ายาวเกินหรือไม่

### 12.7 รถจำลอง 3D (vehicles)

ในมุมมอง 3D (`static/vehicles.js`) มีรถลาก 2 แบบวิ่งเป็นแอนิเมชันตามเวลาจริง: **Auto** = รถมีโคมไฟหอ (แดงตอนรอ · เหลืองตอนเข้าหาจุดจอด · เขียวตอนวิ่งผ่าน) · **Manual** = รถมีคนขับยืน

ตัวควบคุมไม่รู้ตำแหน่งรถจริง ภาพนี้จึงเป็น **การจำลองจากสิ่งที่ระบบรู้** ไม่ใช่ตำแหน่งที่วัดได้ (หน้าจอแจ้งไว้):
- Auto: เซนเซอร์ไกลเจอรถ → รถโผล่ที่ต้นทางแล้ววิ่งเข้าหาจุดจอด · Manual: เซนเซอร์เจอ/มีตั๋ว → รถเข้าจุดจอด
- รถจอดหน้ากล่องเลนตราบที่เลนนั้นไม่ได้เขียว (คิวหลายคันต่อแถว) · เมื่อตัวควบคุมให้เลนนั้นเขียว รถออกตัววิ่งผ่านแยกแล้วจางหาย · เซนเซอร์ยังเจอรถคันถัดไปขณะเขียว รถคันใหม่วิ่งผ่านเลย · คำขอหาย > 5 s รถที่รออยู่จางหาย
- ทิศที่รถวิ่งของแต่ละเลน: ค่า `dir` ใน layout (ปุ่ม “ทิศรถ ↻” ในแถบเครื่องมือของกล่องเลน · 0 = ขวา, 90 = ลง, 180 = ซ้าย, 270 = ขึ้น) ถ้าไม่ตั้ง ใช้ `approach` ของเลน (S = ขึ้น, N = ลง, W = ขวา, E = ซ้าย) และถ้าไม่มี = ขึ้น · ผังตามแบบ T3 มี `approach` ครบ
- ปุ่ม 🚜 รถ เปิด/ปิดรถจำลอง · ไม่ส่งอะไรไปที่ระบบควบคุม

### 12.5 รหัสแจ้งเตือน (diag)

หน้าเว็บสร้างรหัสจากสถานะที่ poll อยู่แล้ว (`static/diag.js`) ไม่ส่งอะไรเพิ่มไปที่ระบบควบคุม และไม่แตะตรรกะไฟ · แสดง: ป้ายที่หัวหน้า (⚠ n) · การ์ดการแจ้งเตือนพร้อมวิธีแก้ · รหัสที่แถวเลน · กรอบแดงที่กล่องเลนบนแผนที่ · แถบแจ้งเมื่อมีเหตุใหม่ · ตารางรหัสทั้งหมดที่ ระบบ › ดูแลระบบ

| รหัส | ความหมาย | มาจาก |
|---|---|---|
| E101 | เซนเซอร์ไม่มีข้อมูล เลนถูกปิด | `reasons` ของเลน = `sensor:<id>` |
| E201 | จอไม่ตอบ เลนถูกปิด | `display_online` = false หรือ reason `display` |
| E301 | ค่าตั้งใช้ไม่ได้ ไม่ควบคุมไฟ | `errors` ของสถานะ |
| E401 | ระบบควบคุมไม่ตอบ | ไม่ได้รับสถานะ (stale) |
| W101 | เซนเซอร์ไม่มีข้อมูล แต่เลนยังใช้ได้ (เช่น C1.2 ของ Auto) | `sensors[].online` = false |
| I501 / I502 | ปิดเลนโดยผู้ใช้ / ปิดในค่าตั้ง | reason `maintenance` / `config_disabled` |

### 12.8 สรุปการไหลของรถตั้งแต่เปิดเครื่อง (flow summary)

กราฟไทม์ไลน์ (12.6) ยังอยู่เหมือนเดิม และมีการ์ด **สรุปตั้งแต่เปิดเครื่อง** อยู่ใต้กราฟ: ต่อเลน = จำนวนครั้งที่เขียว, เขียวเฉลี่ย/ต่ำสุด/สูงสุด, รอเฉลี่ย/สูงสุด, คำขอ/ผ่าน/หมดอายุ, คิวสูงสุด, ผ่านต่อชั่วโมง, สัดส่วนเวลาเขียว, จำนวนครั้งขัดข้อง; รวม = เวลา "ทุกจอ X", ค้างเผื่อเสีย, ว่างไม่มีคิว + ข้อสังเกตอัตโนมัติ (เลนรอนานสุด, เลนใช้มากสุด, คำขอหมดอายุ, เลนขัดข้อง)

- `t3/flowstats.py` (pure logic) รับ status ของ controller ทุก 0.5 s ผ่าน `StateCache.on_state` ในเว็บเซอร์วิส **ไม่แตะ controller** จึงไม่กระทบความปลอดภัย
- เก็บลง `<data-dir>/flow.json` ทุก `web.flow_save_s` (30 s) จึงไม่หายเมื่อ apply config / restart controller
- ช่วงที่เว็บเซอร์วิสหรือ MQTT หยุดเกิน `web.flow_gap_s` (5 s) ไม่นับเป็นเวลา และเพิ่มตัวนับ "ขาดช่วง"
- เวลารอ = อายุของตั๋วตอนออกจากคิว (ออกตอนเลนนั้นเขียว = ผ่าน, ออกโดยไม่เขียว = หมดอายุ)
- `GET /api/flow` (ทุกบทบาท) · `POST /api/flow/reset` (editor เท่านั้น, บันทึก audit)
- ทิศทางรถ (12.7) ตั้งได้ในตัวแก้ไขเลนตั้งแต่ตอนเซ็ตอัปครั้งแรก (เก็บใน `localStorage t3dirs` ก่อนวางบนแผนที่)

### 12.9 วิซาร์ดเซ็ตอัปครั้งแรก (จอสัมผัส Pi · ไม่ต้องใช้โน้ตบุ๊ก)

- Pi เปิดเว็บเต็มจออัตโนมัติ (`scripts/t3_kiosk.sh` + `install/trafficlight-kiosk.desktop`, ติดตั้งโดย `install.sh --t3`) ครั้งแรกสร้างบัญชีแรกบนจอ Pi เอง (`POST /api/setup/first-user` รับเฉพาะ loopback และเฉพาะตอนยังไม่มีผู้ใช้เลย)
- ขั้นตอน: ต้อนรับ → **เบิร์นจอทีละตัว** (เลือกหมายเลขจอ + พอร์ต USB แล้วกดเบิร์น) → ตรวจว่าจอออนไลน์ → ตั้งค่าแยก (เดิม) → วาดแผนที่ (เดิม) → หน้าแผนที่หลัก · กดย้อนกลับได้ · หน้า "ระบบ" มีปุ่ม "เบิร์น/ตรวจจอ" เปิดซ้ำได้ (เช่นเปลี่ยนจอตัวใหม่)
- แสดงวิซาร์ดเมื่อยังไม่มีเลนและยังไม่กดเสร็จเท่านั้น แยกที่ตั้งค่าไว้แล้วจะไม่เห็น
- ตัวเบิร์น (`web/flasher.py`) รัน esptool กับไฟล์สำเร็จรูป `firmware/t3/display<N>/*.bin` ไม่คอมไพล์บน Pi · พอร์ตต้องอยู่ในรายการที่ตรวจพบและไม่ใช่พอร์ตเซนเซอร์ · เบิร์นได้ทีละงาน · ค่าทั้งหมด (จำนวนจอ offset baud flag timeout) อยู่ใน `setup` ของ config
- build ไฟล์เฟิร์มแวร์ครั้งเดียวบนคอมที่มี PlatformIO: `python tools/build_t3_firmware.py` แล้ว commit โฟลเดอร์ `firmware/t3/`
- API: `GET /api/setup/status` · `POST /api/setup/flash` · `POST /api/setup/done` (editor)
- **ยังไม่ได้ทดสอบบน Pi/บอร์ดจริง**: ทดสอบเฉพาะในตัวจำลองและ pytest (esptool จำลอง) · จุดที่ต้องลองจริงคือ esptool เข้าโหมดบูตของ ESP32-S3 ผ่าน USB, kiosk บนระบบเดสก์ท็อปของ Pi (labwc/X11), และคีย์บอร์ดบนจอสัมผัสตอนสร้างบัญชี

## 14. สิ่งที่ต้องทำหน้างาน

1. แฟลชเฟิร์มแวร์ T3 ผ่านสายครั้งแรกทั้ง 5 จอ (หลังจากนั้นใช้ OTA)
2. ติดตั้ง `sudo ./install.sh --t3` บน Pi ของ T3 แล้วตั้งค่าเลนในหน้าเว็บ (หัวข้อ 12.1) และลากเลนวางบนแผนที่
3. วัดระยะพื้นแล้ว (C1.1/C1.2 236, C2 241, C3 234, C4 235, C5 220 cm) → ระยะไกลสุด 190 cm (ต่ำกว่าพื้นใกล้สุด 30 cm) · ต้องแก้ค่าใน Pi ที่ติดตั้งแล้วด้วย (ระบบ › ตั้งค่า › การตรวจจับ)
4. บันทึกสัญญาณจริงของรถ + dolly และ Auto จ่อตูด เพื่อจูน gap hold
5. จับเวลารถเลนพิเศษคันช้าสุดตอนลากของเต็ม เทียบกับเขียว 3 s (ปรับเพิ่มใน config ถ้าไม่พอ)
6. วัดรอบการทำงานจริงเมื่อต่อเซนเซอร์ครบ 6 ตัว
7. ทดสอบ checklist หัวข้อ 15 กับรถจริงก่อนใช้งาน

## โหมดจำลอง (admin เท่านั้น)

- ผู้ใช้ที่ชื่อตรง `sim.user` (ค่าเริ่มต้น `admin`, สิทธิ์ editor) เห็นแถบ "จำลอง" ทางซ้ายของหน้าเว็บ
- เปิดโหมดแล้วตัวควบคุมไม่อ่านเซนเซอร์จริง แต่สร้างเฟรมปลอมต่อเซนเซอร์ (ผ่าน / มีรถหรือมือ / ว่าง / เสีย = ไม่ส่งเฟรม) ผ่านตัวกรองเดียวกับของจริง ตัวควบคุม ไฟ คิว จอ ทำงานตามกติกา T3 ตามปกติ
- ปิดเองเมื่อครบ `sim.max_s` (ค่าเริ่มต้น 1800 s) หรือเมื่อรีสตาร์ตบริการ ไม่เก็บลง settings ระหว่างเปิดมีแถบแดงบอกทุกผู้ใช้
- `sim.pulse_s` = เวลาที่ปุ่ม "ผ่าน" ค้างเป็นมีรถ ห้ามเปิดใช้ขณะมีรถจริงในแยก
